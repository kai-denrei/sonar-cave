## Dead Ends
| Date | What was tried | Why it failed / was rejected |
|---|---|---|
| 2026-05-19 | Registering the service worker unconditionally in main.js (prod + dev) | After any `npm run preview` run, the SW persists at `localhost` and intercepts all subsequent `npm run dev` requests, serving cached HTML/JS forever. Gerald hit this hard: token in the badge stayed on the preview-build value even after multiple hard refreshes against the dev server. Cause: SW is registered per-origin, not per-port-mode; localhost is one origin. Fix: gate registration on `import.meta.env.PROD`, and in dev proactively call `getRegistrations().forEach(r => r.unregister())` + clear `caches.keys()` so users who already hit the trap auto-recover on first reload after the fix. |

## Lessons
- A service worker registered on `localhost` outlives the dev/preview distinction — the origin is the same. Always gate SW registration on a production-build flag. If you don't, the first `vite preview` poisons every later `vite dev` until the user manually unregisters via DevTools. — from dead end on 2026-05-19
- When fixing a stale-SW bug you also have to ship the *recovery* code, because by definition the affected users can't see the fix until the stale SW lets go. The dev-mode branch should not just refrain from registering — it should actively unregister + clear caches so the next reload pulls fresh assets. — from dead end on 2026-05-19
